# 代码动画做法总结（vibe-motion-lab 的结论）

2026-11-15。这份文档总结了 2026-11-12 到 11-15 在本试验场里试过的 [vibe-motion](https://github.com/vibe-motion) 全套工具，以及一条真实成片（朝カフェ ep001）的经验。

**写给谁**：其他项目里要做「代码画动画、出视频」的人或代理。先读第 1、2 节选路线，再读对应的那一节照着做。

**参考代码怎么用**：文中路径都在这台机器的 `~/Documents/workspace_taterboom/vibe-motion-lab/` 下，**只读**。要用就拷进自己项目再改，不要在试验场里改。标「本机」的目录没有入库，只在这台电脑上有。

---

## 1. 结论

- **没有哪个工具能一键出好片。** 好片来自一套做法：声音先行，帧驱动的纯函数，动作写成阶段表，代理自己抽帧看画面。vibe-motion 的价值主要在这些做法，不在组件。
- **对话类短片（有角色、有配音）走「矢量纸偶 + 运镜 + 阶段表表演 + 逐字字幕」**。朝カフェ ep001 角色版用户评「非常棒，几乎达到 90%」。这是本试验唯一被用户验收过的成片路线。
- 工具层面只留 4 样：`disney-animation-rule-skill`（动作方法）、`sound`（找音效，要先改）、`remotion-starter` 的 `HARD_RULES.md`（红线文档）、Remotion 本身。其余的只取方法、当参考，或者不用。

## 2. 按片子类型选路线

| 片子 | 路线 | 验证程度 |
|---|---|---|
| 角色对话短片（配音 + 角色 + 字幕） | 第 4 节配方：Remotion + 矢量纸偶 + disney 阶段表 + 卡拉 OK 字幕 | **用户验收（约 90%）** |
| 纯文字对话串（聊天记录、问答） | 对话气泡流：不清屏，输入框承载「你」的动作。参考 `trials/2b-asakafe/bubble/` | 做成了；用户评「风格没问题，但不适合朝カフェ」 |
| 讲解片（原理、流程、架构） | `remotion-code-motion-explainer` 的六步流程（先拆拍、持续对象表、先做信息最满的主帧），配自写的 QC 脚本；镜头库只当参考 | 做过 22 秒样片，用户未评 |
| 无人值守批量 MG 镜头 | `auto-motion` 的编排：总调度拆镜头，每个镜头一个独立会话，靠风格笔记接力，最后统一验收拼接 | 11 秒样片，用户评「不错、花费不多」 |
| 宣传片 | `brand-launch-video-star` 的节拍表（30 秒排 8–12 拍、每拍一个主动作、转场重叠 6–12 帧）+ `pixel2motion` 的数值档位做标志动画；素材用真实截图 | 只跑过技能样片，**没做真实宣传片**（2A 未做） |
| 三维片头、标志 | `create-vibe-motion-3d`（Three.js + puppeteer 逐帧截图）出 PNG 序列，再合成 | 跑通；不透明、无声 |

## 3. 通用做法（每条都在本试验里验证过）

1. **先有声音，再做画面。** 先定配音和每句时长，时间线由音频时长生成，画面不决定时长。动作锚在「段起点 + 句内偏移」，句内节拍用 ffmpeg `silencedetect` 加 50ms RMS 包络测出来，写成数据。嘴形跟音量走，用 `@remotion/media-utils` 的 `useAudioData` + `visualizeAudio`。
2. **整片表演写成一个纯函数。** 例如 `showAt(t)`，输入全片秒数，输出所有角色、镜头、道具的状态。不读上一帧，不累积。次要动作（头发、泡沫、杯身晃动）用「延迟采样主动作」算出来。好处是可以只算数值、不渲染就检查，也能并行渲染。参考 `trials/2b-asakafe/puppet/src/perform.ts`、`anim.ts`（`track` 关键帧轨道、`pulse`、`settle` 阻尼回稳、`hash` 确定性伪随机）。
3. **每个动作先写阶段表，再选缓动。** 阶段依次是预备、动作、过冲、回稳，次要动作滞后。保持段不能冻住，要有呼吸和确定性眨眼。方法在 `disney-animation-rule-skill`（本机 `.claude/skills/`），技能本身不给数值。可借 `pixel2motion` 的档位：
   - 阶段比例 20:50:30；
   - 预备占主动作的 20–30%；
   - 错开 10–20%；
   - 过冲 1.02 / 1.04 / 1.08 / 1.12；
   - 挤压 10–25%。

   想要「碰」的力度，就用末端保留速度的缓入。
4. **红线（确定性）。**
   - 所有动画由帧号算出。
   - 不用 `Math.random`、`Date.now`，也不用 CSS transition 或 animation。
   - `interpolate` 两端都 clamp。
   - `spring` 的结果再用 `interpolate` 映射。

   规则全文在本机 `trials/05-starter/ext/docs/HARD_RULES.md`。实测代理读了这份文档就多半自觉不犯，所以写进项目的 CLAUDE.md 比装 hook 更有效。
5. **代理必须自己看画面。** 只查尺寸、时长、文件的「校验」查不出问题，问题都是抽帧看出来的。做法：
   - 半尺寸渲整片（`--scale=0.5 --muted`，约 10 秒），再用 ffmpeg 按段落的起点、中点、终点抽帧，用 Read 看图。
   - 做全片拼图：`ffmpeg -i x.mp4 -vf "fps=2,scale=216:-1,tile=10x6" -frames:v 1 contact.png`。
   - 重点查：缺字和豆腐块、注音位置、溢出、版式切换时跳不跳、空白区域、穿模、出画。
   - 发现问题就修，修完再看。朝カフェ角色版自查了三轮，修掉十几处。
   - 脚本参考 `trials/2b-asakafe/puppet/out/qa/qa.sh`。
6. **版式锚在固定槽位。** 全片一种底色。各元素的槽位从头到尾不变，只换里面的内容。换内容时先淡出旧的（约 0.1 秒），再淡入新的（约 0.18 秒），不叠字。
7. **字幕逐字跟音频。** 每句写成「分块 [起字, 止字, 起秒, 止秒]」，注音跟它的汉字一起变色。镜头会推到特写时，字幕放在画框外面，不叠在画面上。参考 `trials/2b-asakafe/puppet/src/script.ts`、`Captions.tsx`、`Ruby.tsx`。
8. **音效对在事件发生的那一帧，并且压在人声下面。** 人声峰值约 −1.5dB，碰杯这类音效约为人声的 1/3，tick 约 −16dB。mp3 有解码延迟（实测晚约 60ms），击打点要提前，渲染后用 ffmpeg 量一下击打点是否对上画面。
9. **分工。** 大活交给子代理并行做，每个子代理拿一份共同说明（参考 `trials/2b-asakafe/BRIEF.md`：台词与音频表、不许改的结构、用户偏好、要用的做法、环境注意、交付物）。主会话负责验收：看拼图和关键帧、扫红线、跑 tsc、量电平。

## 4. 配方：角色对话短片（朝カフェ ep001 角色版）

成片：`trials/2b-asakafe/ep001_puppet.mp4`。基线对照：`baseline.mp4`。分镜阶段表：`puppet/PLAN.md`。做法说明：`puppet/NOTES.md`。工程（约 1800 行）：`puppet/src/`。

**画面**
- 矢量扁平的代码画人物和场景。用户明确不要赛璐珞位图立绘。
- 画框占画面约 57%（1024×1090）。下面是固定文字区：说话人签、日文两行带注音、中文、提示行。

**镜头**
- 写成关键帧轨道，缓入缓出，带约 3% 过冲。
- 镜头跟着说话的人走：全景 → 推到部长 → 甩到「你」→ 倒计时时每秒 punch-in 一次（1.45 → 1.60 → 1.76）→ 拉回 → 碰杯时 4 帧轻微冲击。
- 叠 ±2px 的手持漂移，教学段降到 40%。

**表演，每个都按阶段表写**
- 转身前先反向带一下。
- 被夸时的 take：先下沉眯眼（0.17 秒），再拉伸睁眼（0.13 秒），然后阻尼回稳，头发晚 0.1 秒落下。
- 倒计时：冒汗，每 0.4 秒做一次 2 帧的眼跳，最后咽口水。
- 答完小鞠躬。
- 碰杯：由世界坐标反解两只手的位置，让杯口精确相接，音效击打点对在这一帧。

**教学段**：卡片从画框底部升起，把错误说法划掉，把目标句拆成两步。两个人的头留在卡片上面，继续演。

**还没解决的 10%**（用户没细说，以下是代理自报）：
- 转头只是五官横移；
- 鞠躬没有腰关节；
- 嘴形只按音量分三档，不分音素；
- 「本当に」那半秒里动作太密；
- 教学卡片挡住了托腮的手。

**工作量**：一个子代理约 30 分钟。整片渲染约 15 秒，半尺寸自查一轮约 10 秒。

## 5. 各工具结论

| 工具 | 结论 | 一句话 |
|---|---|---|
| `create-vibe-motion`（Remotion 脚手架） | 留骨架 | 「参数 → 时间线纯函数 → 无状态场景」的结构好；音频清单可由程序生成。官方渲染脚本坏了（`.jsx` 导入），尺寸上限 1280×1440 挡住竖屏 |
| `create-vibe-motion-3d` | 只取部分 | 确定性好（同帧 md5 一致）；不透明、无声，适合单独出三维片头 |
| `disney-animation-rule-skill` | **留用** | A/B 对比用户认可 B 版；给方法和清单，数值要自己定 |
| `pixel2motion` | 只取部分 | 数值档位和 QA 思路好；描边类素材会误报，不出视频 |
| `perspective-illusion` | 只取方法 | 镜头系统、「平时偷换」的错觉设计；带闪烁检查脚本 |
| `brand-launch-video-star` | 只取方法 | 节拍表清楚；校验器只查结构；成片偏模板感 |
| 其余 13 个技能（colorize、candlestick、3d-ticker、vinyl、spotlight、curtain、fisheye、wechat-2d、ruler、fish、earth、chladni、claude-typer） | 固定效果，按需取 | 17 个技能里原样一次跑通的只有 4 个；claude-typer 已失效；明细见 `trials/03-skills/SUMMARY.md` |
| `remotion-code-motion-explainer` | 只取方法 | 六步流程能查出问题，但关卡全是清单、没有脚本；招牌连续画布有「每拍重新入场」的 bug；SRT 驱动缺解析器 |
| `remotion-starter` | 取 `HARD_RULES.md` 和出片流程 | hook 是正则：能被命令行写文件、`.js/.jsx` 绕过，有误伤，tsc 只拦一次；依赖的官方 MCP 已关闭；`qa:still` 写死横屏 |
| `sound` | **留用（先改）** | 靠下载量、评分人数、描述，加 ffmpeg 实测挑 Freesound 音效，方法对；只有一个来源、只下预览版 MP3。原版要先删两处：免确认放行的 Clash 改代理脚本、交付后的付费推销段。改好的副本在本机 `trials/06-sound/.claude/skills/sound` |
| `auto-motion` | 只取编排方法 | 20 分钟、约 $5.5 出 3 个风格统一的镜头。权限全开；README 的 Codex 命令在 0.169 上要改成 `codex -a never exec ...`；输出写死 1080×1440、无声、无字幕 |

## 6. 坑

- **Remotion 4.0.541 在这台电脑上连空工程都加载不出根组件**（"Waiting for root component" 超时）。钉在 **4.0.484**，四个包一起：`npm install remotion@4.0.484 @remotion/cli@4.0.484 @remotion/media@4.0.484 @remotion/media-utils@4.0.484 --save-exact`。asakafe 目前用的就是 4.0.541。
- 并行跑 10 个 `remotion still` 会卡死。改用半尺寸渲整片再抽帧。
- 技能里常有写死的作者环境：`~/.claude` 路径、`/usr/local/bin/python3`、作者电脑上的路径。外部工程没锁版本，已经有两个因为上游变化坏掉。
- 在 VS Code 里的 Claude Code 跑 Electron 工具前，要先 `unset ELECTRON_RUN_AS_NODE`。
- 让代理全自动跑时，**备份和不想让它看到的文件要放在工作目录外面**。它会列上级目录，读到不该读的东西。
- 许可：
  - `skills`、`sound`、`auto-motion` 仓库没有许可证文件；
  - `remotion-starter`、`remotion-code-motion-explainer` 是 MIT；
  - `create-vibe-motion` 的 npm 包声明 MIT；
  - 克拉尼的素材是 CC BY-NC。

  抄进公开仓库前要先确认。
- 音效只用 CC0，出处记在 `CREDITS.md`。

## 7. 没验证到的

- **宣传片（2A）和讲解片两条路线对比（2C）没有做**，用户决定先收尾。所以第 2 节里宣传片和讲解片两行只有技能样片的依据，没有真实成片。
- 1.1、1.2、1.4 和 brand-launch 样片，用户都没有评价。
- 音素级口型、2D 纸偶的转身和腰部关节，都没有解决方案。
- `auto-motion` 的失败重试机制没触发过；HyperFrames 技能是否被删减过，没和上游比对。
