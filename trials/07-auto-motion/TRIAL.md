# 07 全自动 auto-motion

日期：2026-11-14
版本：vibe-motion/auto-motion@17ead62（2026-07-23），无许可证文件；codex-cli 0.169.0（ChatGPT 登录），Claude Code 2.1.323（每个镜头会话用的是 Opus 5.5），HyperFrames 0.9.41

## 它是什么

一份给 Codex 的任务说明（`PROMPT.md`，50 行）加一个单镜头模板（`exampleFolder/run-claude-ai.sh`）：
1. Codex 读 `transcription.srt`，按语义粗分镜头，时长必须首尾相接、覆盖全程。
2. 每个镜头建一个目录，拷模板和 6 个 HyperFrames 相关技能，填好镜头文案和时长。
3. **一个接一个**用 `claude -p --dangerously-skip-permissions` 让 Claude Code 独立做这个镜头：联网查名词、下 logo，用 HyperFrames（HTML + GSAP，浏览器逐帧渲染）出 1080×1440、30fps、无声 mp4。
4. Codex 检查规格，用 ffmpeg 拼成 `final.mp4`。

## 做了什么

- 为了省钱，按用户的意思只用自带字幕的**前 7 条**（0.3–11.366 秒，到一句话结尾）。原文件备份成 `transcription.full.srt`。
- 照 README 在 `ext/` 里运行。**README 的命令在当前 Codex 上直接报错**：`codex exec ... --ask-for-approval never` 提示 `unexpected argument '--ask-for-approval'`。0.169 版把这个参数放在顶层，改成等价的 `codex -a never exec --cd . --sandbox danger-full-access - < PROMPT.md` 后跑通。

## 风格为什么能统一

`PROMPT.md` 只说「可以改写提示词让镜头更贴合文案」，没提一致性。是 **Codex 自己加的**：它给镜头 2、3 的提示词加了一段「全片共 3 个镜头，保持视觉一致性，读取 ../scene-001/STYLE_NOTES.md 延续基调，并写下本镜头的 STYLE_NOTES」。镜头 1 的 Claude 也自发写了一份 45 行的 `STYLE_NOTES.md`（色板、字体、固定版式元素、语义配色约定，还建议镜头 2 从「NOW」标签接上）。后面的镜头直接复制了镜头 1 的工程骨架和字体。

这也是假设 17「镜头之间风格不连贯」不成立的原因，但它靠的是这次的模型自觉，`PROMPT.md` 里并没有写。

## 自检做了什么

- 每个 Claude 会话：用 `hyperframes check` 查错，用 `hyperframes snapshot` 抽关键帧看，按看到的改位置、字号、时间，再渲染。
- Codex：量每段规格；发现镜头 1 的编码参数和后两段不同，统一转码再拼；做了首尾和两处接缝的拼图检查；逐帧哈希确认没丢帧、没调换。写了 `DELIVERY.md` 和可重跑的 `assemble-final.py`（不重新叫 Claude）。
- 这比作者自带的 `auto-test/validate.sh`（只查分辨率、帧率、时长、无音轨）多得多，但都是模型自发做的，`PROMPT.md` 只要求「拼接前确认统一规格」。

## 要注意的

- **权限全开**：Codex 用 `danger-full-access` + 永不确认，每个 Claude 会话用 `--dangerously-skip-permissions`。这次它们联网搜索、`curl` 下了 logo 和 Google Fonts 字体、`npx` 装了 HyperFrames，都在镜头目录里，没有越界。但系统层面不拦。
- **会读到目录外的东西**：镜头 3 的 Claude 列出上级目录时读到了我留的 `transcription.full.srt`。画面里的「GLM 子 agent」是后文才讲的内容（第 9 条），这次影响不大。真用时备份不要放在工作目录里。
- 依赖网络：Google Fonts、logo 下载、npm。
- 输出固定 1080×1440，不是 1080×1920；无声、无字幕，配音和字幕要在别处加。
- 仓库没有许可证文件。

## 和配音、音效怎么接

没有。镜头时长按字幕时间切，所以把原配音按同样的时间轴叠上去应该能对上（这次没有配音文件，没试）。字幕要后期另烧。

## 用户评价

（待用户看 `ext/final.mp4`）

## 好的地方

- 只给字幕，20 分钟出一条风格统一、可看的 11 秒 MG 动画，全程无人值守。
- 分工清楚：Codex 只调度和验收，Claude 只做单个镜头。每个镜头独立目录、独立日志，失败可以单独重跑。
- 这次的模型自发补上了风格笔记和画面自检，交付报告很完整。
- 花费和时间比作者的证据好很多。

## 不好的地方

- README 的启动命令在当前 Codex 上已经坏了（参数位置变了）。
- 一致性和画面自检靠模型自觉，不在流程契约里；换模型或运气不好就可能没有。
- 权限全开。
- 镜头之间没有过渡（硬切），镜头是互相独立做的，跨镜头的连续动作只能靠风格笔记里的约定。
- 竖屏规格写死 1080×1440；HyperFrames 的技能里没有音频相关内容，是否像作者说的那样删减过，没和上游对比。

## 结论

**只取方法。** 「总调度拆镜头 → 每个镜头一个独立会话 → 风格笔记接力 → 统一验收拼接」这套编排值得留，尤其是风格笔记接力和逐镜头日志。但朝カフェ不适合直接用：它是对话短片，需要角色、配音和字幕对齐，跨镜头的连续性比独立的 MG 镜头重要。2C 讲解片对比时可以用它跑一版做对照。
