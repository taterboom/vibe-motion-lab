# 03 技能 perspective-illusion

日期：2026-11-13
版本：skills 仓库 f558ec4（`.claude/skills/perspective-illusion/`）；three 0.170.0，playwright 1.60.0（技能 Quick start 指定的版本）

## 做了什么

README 没有给这个技能的触发原话，只有一句描述和 demo.gif。照 `SKILL.md` 的 Quick start 原样走：

```
printf '{"type":"module"}' > package.json && npm i three@0.170.0 playwright@1.60.0
cp -r <skill>/templates/* .
cp scramble_night.html scene.html
node render.mjs scene.html x --stills=0.3,1.5,3,6,8.5      # 静帧
node render_fast.mjs scene.html out/preview.mp4 --preview   # 半尺寸预览
node render_fast.mjs scene.html out/final.mp4               # 正式
python blink_map.py ffmpeg out/final.mp4 out/blink.png      # 闪烁检查
```

选 `scramble_night.html`（夜晚雨中的十字路口，带人群、广告屏、湿地面反射），因为技能说它是"唯一带快速渲染钩子的模板，新场景最好从它开始"。12 张 cutouts 随模板一起拷过来，广告牌里用到了。

另外做了三件对比：
- `render_smooth.mjs` 跑 `street.html` 和 `street_plus.html`；`render.mjs` 拍 `street.html` 静帧。
- "改一处"：照技能自己写的"把 scramble_night 改成白天"清单，做了 `day/scene_day.html`（改法在 `day_patch.mjs`）。

## 跑通了吗

基本一次通过，有几处小坑：

1. 本机没有 playwright 1.60 对应的浏览器，要先 `npx playwright install chromium-headless-shell`（92MB，6 秒，进的是用户缓存）。技能没写这步。
2. Quick start 里的路径是作者自己机器的：`cp -r ~/simcraft/skills/video/perspective-illusion/templates/*`。照抄会失败，要换成本地技能目录。
3. Quick start 第 5 步 `python3 ~/simcraft/skills/video/vox-explainer/scripts/motion_check.py` **没有随技能发布**（vox-explainer 不在这 17 个技能里）。这一步跳过。
4. `blink_map.py` 要 numpy 和 Pillow，用技能目录下的 `uv venv` 装。
5. **模板表写错了一处**：表里说 `street.html` 用 `render_smooth.mjs`，但 `street.html` 没有 `window.probe`，`render_smooth` 等它 30 秒后超时退出。`street_plus.html` 有 probe，能跑。`street.html` 只能用 `render.mjs`。
6. `render.mjs` 写死 210 帧（7 秒）、1920×1080、30fps，`scramble_night` 是 10 秒的循环，用它出整片会少 3 秒。它只适合拍静帧和 7 秒的老模板。
7. `render.mjs --stills` 永远写到页面目录下的 `stills/st_<秒>.png`，换页面拍同一时间点会互相覆盖（我拍 `street.html` 时把 `scene.html` 的 `st_3.png` 覆盖了，重拍了一次）。
8. `blink_map.py` 把时间按 60fps 换算写死，对 30fps 的预览报的秒数是错的；技能本来也说只在正式片上看闪烁。

## 三个渲染脚本的区别

| 脚本 | 做法 | 需要页面提供 | 实测速度 |
|---|---|---|---|
| `render.mjs` | 每帧 4 次子帧截图，ffmpeg `tmix` 平均成运动模糊（180° 快门）。写死 7 秒 30fps | `render`、`READY` | 静帧 5 张 8 秒 |
| `render_smooth.mjs` | 每帧 32 个槽、360° 快门；用 `probe` 量画面移动多少像素，动得多就多渲染几次（4–32 次），每次加亚像素抖动抗锯齿；每次都截一张 PNG 交给 ffmpeg 平均 | `render`、`READY`、`probe`（可选 `setJitter`） | street_plus 0.5 秒（30 帧，镜头慢）16 秒；技能说比 fast 慢好几倍 |
| `render_fast.mjs` | 同样的自适应运动模糊和抖动，但在页面里用 `renderMany` 在 GPU 上累加，每帧只截一张图出浏览器；`--preview` 半尺寸 30fps 少采样 | `render`、`READY`、`probe`、`renderMany` | 预览 10 秒片 1.0 分钟；正式 600 帧 60fps 共 8280 次渲染 9.1 分钟（技能说约 30 分钟，这台机器快） |

技能要求：用 `scramble_night` 这类新模板就用 `render_fast`，先看静帧，再看预览，预览通过才出正式。

- `out/final.mp4`：1920×1080，60fps，10 秒，600 帧，48MB，无声，循环
- `out/preview.mp4`：960×540，30fps
- `out/blink.png`：闪烁热图
- `stills/`：静帧；`day/stills/`：白天版静帧
- `contact.png`：8 帧（每 1.25 秒一张，在每段中间取）

拼图里看到的（照实说）：
- 第 1、4、7 格是长焦"平面"镜头：整条街压成一张立面图，广告牌、招牌、路灯叠成一面墙，确实像一张插画。第 4 格和第 1 格的广告内容换了（屏幕轮播）。
- 第 2 格是"虫眼"低机位广角：街道纵深一下子打开，天空的粉紫云是按视线方向画的，有轻微的运动模糊。
- 第 3 格是转角俯视：人群、雨伞、斑马线、出租车，信息量很大。
- 第 5、6 格是高位对角和第二个转角视角，第 6 格巴士、出租车、人群的细节都在，透视干净。
- 第 8 格是最快的那次回拉（回到平面），运动模糊很重，整格糊成一片。按技能设计这是故意的（360° 快门，快动作拖影），但在静帧里看就是糊的，实际观感要用户看。
- 墨线、两色明暗、湿地面倒影、雨丝都在。人物远看是一堆小人，近处像手办，技能自己也承认"用形状拼的人像手办"。
- 人物和广告里的角色是 cutouts（作者用图像模型生成的原创角色），品牌都是编的。

量化检查：
- 循环接缝：第 0 帧和第 599 帧平均像素差 1.39（0–255），相邻帧在快动作处是 21.9，接缝基本看不出。
- `blink_map`：125 个近静止帧，3342 个像素（640×360 里占 1.45%）闪烁超过 5%。热图显示主要在左边的大广告屏和左侧楼面的窗框线上，在第一个平面镜头里。广告屏轮播是有意的，楼面窗框线的闪烁不是。没有改前改后的对比，不好说算多算少。

## 方法（这个技能写下来的做法）

**错觉怎么造：** 一条长轴（街道、货架通道、站台）沿 -z 铺开，上面有很多在不同深度重复的东西（电线杆、灯、招牌、人）。用 2° 左右的长焦从 400 米外看，深度被压没，整个场景读成一张平面图。然后做推拉变焦（dolly zoom）：焦平面处的取景宽度 `W` 不变、视角 `fov` 变大、相机同时前推，主体大小不变而背后的空间拉开。再绕焦点转到转角视角，每个转角都先用长焦（平），再变广角（立体）。**画面是平的时候偷偷挪东西**（`lay` 0→1，一排锥桶变成对角线），等纵深回来，观众发现排列变了。

**相机：** 永远水平不俯仰，竖线永远竖直（像建筑图）。"往下看"靠升高相机加镜头移轴（改投影矩阵的 `elements[9]`），不是倾斜。每个镜头是一个对象 `{x, y, zf, W, fov, H, el, yaw, lay, cs}`，公式是 `D = (W/2) / tan(fov/2)`，相机放在焦点后 D 米。

**时间：** 所有参数（`W`、`fov` 取对数）过关键帧，用 Fritsch–Carlson 单调三次插值，速度连续不跳；保持段加 4% 的轻微漂移（`W×0.96`），不冻住。循环顺序：平 → 低机位广角 → 转角（平再开）→ 回平（这时换排列）→ 高位对角 → 另一个转角 → 低机位 → 平。10 秒刚好，7 秒太赶；改长度就整体缩放关键帧时间。所有动的东西（行人、雨、屏幕、车）在一个循环里走整数个周期。

**画风：** 四个渲染通道（颜色、法线+深度、无光照平涂色、只有太阳的阴影遮罩），最后一个着色器合成：深度/法线/颜色变化处描墨线，两色明暗不做渐变，只在投影里画影线（世界坐标锚定），天空按视线方向画。

**质量：** 一张逐项清单（平面镜头是否真平、每次运镜是否有揭示、线条是否干净、循环接缝……），要求"像插画师一样每张静帧找出最弱的三处，改完再看"，再加 `blink_map` 查闪烁。

## 能不能搬到别处用

- **能搬的：** 镜头参数化 + 推拉变焦公式 + 单调三次插值的关键帧系统（`place()` 和 `shotAt()` 加起来约 40 行，和场景无关）；"平的时候偷换"的错觉设计；按 `probe` 量屏幕位移来决定运动模糊采样数的渲染器；渲染器和页面之间的接口约定（`render(ms)`、`probe`、`setJitter`、`renderMany`、`READY`），任何 three.js 页面照着实现就能用它的三个渲染器；"动的东西每个循环走整数周期"保证无缝循环。这些对 Remotion 里做 3D 运镜（比如 `create-vibe-motion-3d`）也直接适用。
- **搬不动的：** 画面本身。一个场景 1000 行手写 three.js，几千个物件，"第一版总是空的，好看靠一轮轮加细节"。换一个场景基本等于重写场景部分。
- **改一处实测：** 照技能的"夜改日"清单改白天，10 处文本替换（`day_patch.mjs`），写和跑静帧共约 2 分钟。出来的白天版天空、阳光、阴影都对，但有残留：窗户还是黄格子（是贴图里画的，不是自发光）、路灯光锥还在、没雨了人还打着伞。说明清单只覆盖了光照和后期，场景里的夜晚内容要另外清。

## 和配音、音效怎么接

完全没有声音。渲染脚本直接 pipe 进 ffmpeg 出无声 mp4。片子是 10 秒循环，适合配一段可循环的环境声（雨声、人声嘈杂），要另外在 ffmpeg 或 Remotion 里合。运镜的关键帧时间都在 `KEYS` 里，可以拿来对音效。

## 好的地方

- 开箱就能出很高质量的片子，跟 demo.gif 一致。从拷模板到出正式片不到 15 分钟，大部分是机器在渲染。
- 方法写得非常具体：每个参数什么意思、什么数值、为什么（"10 秒顺、7 秒赶""0.4 米以内的面会闪"），坑和对策列成表。
- 自查做得重：静帧清单 + 预览 + blink_map + probe 驱动的运动模糊。和 `create-vibe-motion` 的"别自查，让用户看"正好相反。
- 三个渲染器的页面接口约定清楚，可以复用。

## 不好的地方

- Quick start 里是作者机器的绝对路径，`motion_check.py` 没随技能发布。
- 模板表把 `street.html` 配给 `render_smooth`，实际跑不了。
- `render.mjs` 写死 7 秒，跟最好的模板（10 秒）不配；拍静帧会覆盖。
- 场景是巨型单文件（scramble_night 1051 行），改场景成本高；画风绑定 three.js + 自定义后期，和 Remotion 工程不在一个体系里（是 Playwright 截图 + ffmpeg）。
- 正式片 48MB / 10 秒，运动模糊在最快的回拉上很重。

## 结论

只取某部分。成片可以直接当"城市/街景插画循环"素材用（换内容要大改）。真正值得留的是方法：推拉变焦 + 水平相机 + 单调三次关键帧的镜头系统、"平的时候偷换"的错觉设计、按屏幕位移自适应的运动模糊渲染、闪烁检查。适合片头、转场、品牌空间感镜头；不适合朝カフェ这类角色对话片，除非拿它的镜头系统做背景运镜。
