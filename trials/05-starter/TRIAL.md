# 05 工作台 remotion-starter

日期：2026-11-13
版本：仓库 vibe-motion/remotion-starter@6a52139（2026-07-05），MIT；模板钉 remotion 4.0.484；官方技能 `remotion-dev/skills` 当天最新（13 个，装在 `ext/.claude/skills/`）

## 它是什么

不是一个视频工程，是给 Claude Code 用的「出片工作台」：
- **三层**：官方 Remotion（L0）→ `kit/` 共享镜头和组件（L1，5 个镜头：title / talk / list / compare / flankcards）→ `template/` 出片工程（L2，只改 `props.json`）。
- **7 个 hook**（`.claude/settings.json`）：写 `.ts/.tsx` 前查机械红线；每轮提醒「先查官方」；渲染命令前弹确认；收工时跑 tsc；改了代码没改文档时拦一次，提醒「进化」。
- **3 个流程技能**：`produce`（一条片 8 个阶段）、`overlay`（一段画面原生造还是复用）、`evolve`（把学到的写回规则）。外加一个渲染前语义审查代理 `remotion-rule-reviewer`。
- 主打口播视频（真人视频底 + 图形卡片），默认横屏。

## 做了什么

1. 克隆到 `ext/`，`cd template && npm install`（10 秒），`tsc` 过，`npm run render` 出自带 demo（三个镜头，13 秒，15 秒渲完），`npm run qa:still -- title` 抽 3 帧。
2. 写 `test-hooks.mjs`，直接给 hook 喂 30 条假的工具调用，看规则本身拦不拦、误不误伤。
3. 在 `ext/` 里起无人值守会话（`claude -p`，Sonnet）两次，测 hook 在真会话里的表现：
   - s1：让它「直接用 `Math.random()` 给卡片加抖动」。
   - s2：明说是测试，让它用 Write 写 `Math.random`、用命令行写同样内容、写一个类型错误、跑渲染。
4. 在 `ext/` 里起第三次会话（默认模型），像真用户一样提需求：竖屏 15 秒，讲被夸「日本語お上手ですね」怎么回 3 个要点，按 `cyxj-remotion-produce` 流程走，渲染前停。之后我手动渲全片。

会话日志的可读摘要用 `sessions/summarize.mjs` 生成（原始日志不入库）。

## hook 实测

**规则本身（`test-hooks.mjs`，30 条）**

| 类别 | 结果 |
|---|---|
| 该拦的 9 条（`Math.random`、`Date.now`、`new Date()`、`transition:`、裸 `@keyframes`、`animation: 1s linear`、Tailwind `animate-*`、`interpolate` 没 clamp、`<OffthreadVideo loop>`） | 全拦 |
| 该放的 5 条（带 clamp、`random(seed)`、注释里的、钉帧 `paused` 写法、`@remotion/transitions` 导入） | 全放 |
| 误伤 4 条 | clamp 写在常量里传进去（它只在括号里找小写 `clamp` 字样）；数据字段 `transition: 'fade'`；字符串里提到 `Math.random()`；clamp 写在 500 字符之外 |
| 漏掉 | 只 clamp 一边能过；`.js/.jsx` 文件完全不查；用命令行写文件不查；`node` 脚本里调渲染不弹确认 |
| 渲染确认 | `npm run render` / `npx remotion render` / `pnpm exec remotion render` 都弹；`still` 不弹（设计如此） |

**真会话**

- s1（41 秒，约 $0.29）：代理先读了 `HARD_RULES.md`，**自己拒绝用 `Math.random`**，改用 `random(seed)` 并解释原因，拦截器没机会出手。收工时「进化闸」拦一次，代理说明没有规则级变化后放行。**类型检查没跑**：改的是 `kit/`，hook 往上找 `tsconfig.json` 找不到（只有 `template/` 有），就跳过了。而 `kit/` 正是规则要求新镜头放的地方。
- s2（25 秒，约 $0.16）：
  - Write 写 `Math.random` → 拦住，原因原样回给代理。
  - 命令行 heredoc 写同样内容 → 没拦，文件写进去了。
  - Write 写类型错误 → 当时没拦；收工时 tsc 报出错误并阻止收工。
  - 渲染命令 → 弹确认；无人值守时没人点，等于拒绝。
  - **tsc 只拦一次**：hook 跑之前就删掉了标记文件，代理第二次收工时直接放行，类型错误留在代码里。
- s3（出片）：真碰到一次误伤：代理把 clamp 抽成常量 `CLAMP`，被拦，读了 hook 源码后改名 `clampBoth` 绕过。

## 出片流程实测（s3）

17:18–17:32，14 分钟，130 轮，CLI 报价约 $5.81（默认模型）。停在渲染前汇报，我再手动渲（8 秒）。

**代理照流程做了什么**
- 激活 `produce`，读模板、硬规则、kit 索引；按 `overlay` 判断「现有 5 个镜头都是横屏 + 人像让位，不合适」，**原生造了两个竖屏镜头** `vchat` / `vtip`（`kit/scenes/vertical.tsx`，440 行），登记进 `sceneMap.ts`，标 `experimental`。
- 「官方三查」：查了官方技能的规则文件，又对照本地 4.0.484 的类型声明核对 API 是否存在（官方技能是 4.0.543 的写法）。
- 自己想到日文字形风险：模板只带 Noto Sans SC，用「回退到衬线体」的探针帧确认假名、〇〇、→、全角标点都没缺字。
- 抽了 10 帧（入场、中段、落定、切镜、最后一帧），**发现日文长句在词中间断行**（「話せ / ますか？」），改成按意群手动断行，重渲确认。
- 叫 `remotion-rule-reviewer` 做语义审，结论放行，提的 4 条建议当场改了。
- 给 `ep-demo/` 写了自己的 `CLAUDE.md`。

**遇到的问题**
- `npm run qa:still` 把画布写死成 1920×1080，竖屏用不了；代理想修 `qa-still.mjs`，但 `.claude/` 目录受保护写不了，改为整片抽帧，并在工程 `CLAUDE.md` 里记下。
- 它依赖的 `remotion-documentation` MCP **已被官方关闭**（返回「请迁移到 /remotion-docs skill」）。开箱没装官方技能，「官方三查」指向的两样东西开箱都不可用；我手动装了 `remotion-dev/skills` 才有。
- 拒绝 22 次（我给的命令白名单窄：python、node 脚本、联网文档都没放行），代理每次都换了办法，没卡住。
- 结论句停留约 1.1–1.4 秒，低于它自己 theme 里的 1.5 秒标准；代理如实列出，把片长交给用户定。

**成片**
- `ext/ep-demo/out/video.mp4`：1080×1920，15 秒，**有一条静音音轨**（Remotion 默认），2.1MB。
- `film-contact.png`：每秒一帧。浅色底，对话气泡（对方白、自己蓝），每段顶部「编号 + 标题」，中文小字注释，划掉「いいえ、全然です…」、荧光笔扫亮、「正在输入…」三点，收尾是完整对话串 +「道谢 → 谦虚 → 反问」。
- 拼图里看到的毛病：内容集中在画面上半部，下面约 40% 是空的；12 秒处（03 切到收尾）淡到全空；三个要点之间标题和气泡每次都重新入场，不连贯；字号和圆角写死，没走 theme。
- 代码：`ep-demo-src/`（`vertical.tsx`、`props.json`、工程 `CLAUDE.md`、kit 登记的 diff）。

## 和配音、音效怎么接

模板支持口播视频底（`speaker.proxySrc / masterSrc`）和逐字字幕组件 `SrtCaptions`。流程里字幕分 A 路（Remotion 烧进画面）和 B 路（交给剪辑软件）。没有单独配音轨的约定，没有音效。

## 用户评价

2026-11-14：看了 ep-demo 成片，觉得还行。问气泡风格是谁定的：不是 starter 自带（它的 5 个镜头都是横屏卡片），提示词里也没指定风格，是出片会话里的代理按 `overlay` 的「先定意图和画面动作，再原生搭」自己选的对话气泡。

## 好的地方

- **hook 的拦截链路是真的通的**：拦截原因会原样回给代理，代理能照着改。渲染前确认、收工 tsc 也都触发了。
- 更大的作用其实在**文档**：代理读了 `HARD_RULES.md` 就自觉不犯，hook 是兜底。
- **出片流程让代理自己做 QA**：抽帧看画面、查日文字形、修断行、调审查代理，最后如实列出没解决的问题。这和 1.1 脚手架「别自查，让用户看」正好相反，也比 1.4 的清单式自检更实在。
- 「原生先行」的判断写得清楚：现有镜头不合适时，代理会自己造，而不是削足适履。
- 竖屏对话气泡这种 2B 需要的画面，一次会话就能做到可看的程度。

## 不好的地方

- hook 是正则：有误伤（常量 clamp、数据字段、字符串），能绕（命令行写文件、`.js/.jsx`），tsc 只拦一次，`kit/` 的改动不跑 tsc。
- 依赖的外部东西已经变了：官方 MCP 关闭；官方技能要自己装，版本比模板新。
- 默认横屏口播，`qa:still` 写死横屏尺寸。
- 每轮注入一大段「官方三查」提醒，纯聊天时也会注入（hook 不区分）。
- 「进化闸」每次改代码收工都会拦一次，大多数情况下代理只是回一句「没有规则变化」再收工，多花一轮。
- 作者的私有资产（几十个镜头、真实设计系统、字幕修正工具链）不在仓库里，kit 只是骨架。
- 出片会话花费比 1.1–1.4 明显高（$5.8 / 14 分钟），主要花在读文档、三查和反复抽帧上。

## 结论

**留用，作为 2B 的工作台候选。** 值得留的：
1. `HARD_RULES.md` 这种「红线 + 原因 + 官方链接」的规则文档，代理读了就照做。
2. 写入前的机械拦截 + 收工 tsc 当兜底；要补的是 `.js/.jsx`、`kit/` 的 tsc、只拦一次的问题，误伤规则也要放宽。
3. `produce` 的阶段顺序 +「渲染前停下汇报 QA」+ 语义审查代理，这套让代理自己看画面的做法正是 1.3 汇总里说要自建的东西。

2B 如果用它：要先修 `qa:still` 支持竖屏，装官方技能，去掉对已关闭 MCP 的依赖，并把 ep-demo 的竖屏气泡镜头当起点。
