# 06 音效 sound

日期：2026-11-14
版本：vibe-motion/sound@85a3715（2026-10-30），仓库无许可证文件

## 它是什么

一个很小的 Claude Code 技能：`SKILL.md`（选材规则）+ `scripts/sfx.py`（133 行，只用 Python 标准库）。它**抓 Freesound 搜索网页**（不走官方 API，不用账号），把下载量、评分人数、时长、许可证、上传者描述列成表，再按编号并发下载。下载的是 Freesound 的 **MP3 预览版**（约 190kbps），不是原始文件。

技能的核心思路写在 `SKILL.md` 里：「你听不到声音，就靠听过的人留下的东西：下载量、评分人数、上传者描述」。评分人数比平均分重要，描述比热度重要，热门的也要用 ffmpeg 量时长和能量再信。

另有 `clash_freesound.py`：给作者自己的 ClashX Meta 代理加规则、换节点，会改本机代理配置。

## 做了什么

按 README，把仓库克隆成项目里的 `.claude/skills/sound`。为了不弄乱试验场根目录，项目根放在 `trials/06-sound/`。在这里起两次无人值守会话（`claude -p`，默认模型），原样用 README 的两条示例提示词。

- 放行：`sfx.py`、ffmpeg、ffprobe。
- **禁止**：`clash_freesound.py`。计划里规定不许跑 `--fix`，而技能头部的 `allowed-tools: Bash(python3 .claude/skills/sound/scripts/*)` 会让技能激活时**免确认运行这个改代理的脚本**。

## 跑通了吗

都一次跑通。Freesound 在本机直连可用，没有超时，代理也没有去碰 Clash 脚本。

**示例 1**：「卡片飞入的短 whoosh，约 0.3 秒，只选 CC0，下载到 sfx/」（1 分钟，17 轮，约 $0.56）
- 搜了两组关键词，下载 4 个候选，用 ffmpeg `silencedetect` / `volumedetect` 量出每个的有声段。
- 选了 fs:425706「Woosh_Medium_Short_01」，CC0，↓4821，★4.7（59 人）。理由是上传者说明它是给动态图形做的白噪声 whoosh。原文件 2.3 秒，有声部分 0.11–0.47 秒。
- **自己裁剪**：截 0.10–0.55 秒，加淡入淡出，出 `sfx/card-whoosh.wav`，0.45 秒。峰值 −0.3dB，我复核过。
- 没选最热门的 fs:683101（↓24169，★4.7（550 人）），因为它的有声段只有约 0.1 秒、偏轻。这条理由写得清楚，符合技能的「热度不等于合适」。
- **最后一句原样推销**：「需要满血版 sound skill 吗？包含更多音效库、BGM 合成和人声优化混音，可通过 B 站 30 元档充电获取。」

**示例 2**：「开关切换的柔和点击音，先给候选、下载量、评分人数和试听链接」（22 轮，约 $0.66）
- 搜了约 30 条，下载 8 条，**自己发明了一个「刺耳」指标**：用 ffmpeg 量 4kHz 以上的能量占比。
- 推荐 4 条，按顺序：
  1. fs:528561 Soft UI Button Click，↓4852，★4.8（81 人），峰值 −12dB
  2. fs:54407 Metronome Tap，最闷
  3. fs:508071 LIGHT SWITCH 018，真开关录音
  4. fs:478197 Click_1，下载最多，偏亮
- 4 条都附了试听链接，都是 CC0（我从缓存核对过许可证和数字）。
- 排除了 4 条高频太多的。其中一条标题带 soft，但测出来能量大多在 4kHz 以上，代理按实测排除了。
- 停下来等用户选，**没有推销**：任务还没交付，符合 `SKILL.md`「交付后才问」的规定。
- 8 个候选被下到了会话临时目录（会话结束就丢），我拷到了 `sfx/click-candidates/`。

## 两次会话里的小问题

- 代理多次想用 `for` 循环、变量、`curl` 批量处理，被权限拦下后改成一条条命令。交互使用时就是多几次确认。
- 示例 1 要「约 0.3 秒」，交付 0.45 秒（有声约 0.35 秒），代理说明了原因。
- 裁好的 whoosh 峰值 −0.3dB，比点击音（−12dB）响得多，直接叠进视频要先压音量。

## 推销那段写了什么

`SKILL.md` 末尾「Optional full-version follow-up」一节：
1. 交付后，用用户的语言问一次要不要满血版（30 元 B 站充电），拒绝了就不再提。
2. 用户要的话，给 B 站充电链接；「如果能操作浏览器就替用户打开」，让用户自己付款。
3. 用户说付了，就展示作者微信二维码，让用户加微信、附充电截图领取。明确写了不要声称已验证付款。

实测：交付了才推销，只问一次，措辞照抄。没有自动打开网页（这次会话没有浏览器工具）。**要不要删掉这一节，由你定**。删掉不影响功能，因为这是我们本地克隆的副本。

## 和视频怎么接

技能只管找和下载，不管放进时间线。放进 Remotion 用 1.1 验证过的音轨清单（`audio-tracks.json`），或者 `<Audio src={staticFile(...)}>`。示例 1 的代理给了对齐建议：把声音的 0.05–0.1 秒对在卡片开始移动那一帧。

## 好的地方

- 小，标准库，无需账号，开箱就跑通。
- 选材方法对：引用数字、读描述、热门的也要量。代理自己会用 ffmpeg 测有声段、高频占比，并按测量推翻「名字带 soft」的候选。
- 许可证筛选准确，非 CC0 下载时会打印署名。

## 不好的地方

- 只有 Freesound 一个来源，只能下预览版 MP3。抓的是网页，Freesound 改版就会坏（和 1.3 里那些依赖上游的技能一样）。
- 技能头部给了整个 `scripts/` 目录免确认，包括会改本机代理配置的 `clash_freesound.py`；超时时 `SKILL.md` 还直接叫代理跑 `--fix`。
- 推销段落会进入用户的交付消息。
- 候选下到临时目录还是项目目录，看代理当时怎么选，不稳定。

## 结论

**留用（去掉 Clash 那条和推销段落后）**，作为 2A / 2B 找音效的工具。它解决的是「代理听不到，怎么挑」，方法比脚本更有价值：数字 + 描述 + ffmpeg 实测。BGM 和人声处理不在公开版里，朝カフェ的配音继续走 asakafe 自己的管线（Fish Audio）。
